** Automaton infrastructure
- Where :: =carcara/src/automata/= (new module: =mod.rs= 1,336, =operations.rs=
  569, =utils.rs= 322, =parser.rs= 213, =dsu.rs= 97 lines)

  Also small hooks elsewhere, listed below.

* =la_generic= over positive equalities (~40 lines)

- Where :: =checker/rules/linear_arithmetic.rs= (+17),
  =checker/error.rs= (=CannotAddOperators=), =tests/rules/linear_arithmetic.rs= (+23)
- What :: main handles =(not (= ...))= literals but not positive
  equalities (whose negation is a disequality).  The branch represents
  the negated =~== as =Operator::Distinct=: at most one disequality may

  refactor during the merge; the original =CmpOperator=-based version
  was dropped.)
- Touches on main :: three small match arms in an existing rule + one
  error variant.  Has tests, incl. the two-disequalities negative case.

* Polyeq n-ary support (~106 lines)

- Where :: =ast/polyeq.rs=
- What :: polyeq treats n-ary operator applications modulo their
  associativity shape (chainable / left- / right-assoc expansion), so
  e.g. =(and a b c)= is polyeq to =(and (and a b) c)=.  Uses main's
  =Operator::nary_case= (the branch's own copy of that classification
  was dropped in the merge in favor of main's).
- Touches on main :: the polyeq comparator only.  Behavioral: polyeq
  (and thus =refl=, =assume= matching, etc.) becomes more permissive —
  worth benchmarking when upstreaming since polyeq is hot.
