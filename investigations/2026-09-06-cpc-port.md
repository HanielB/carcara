# CPC checking on the bv-fixes base: port, sweep and status

Branch `cpcCheck-bv` (worktree `wt-cpc`), created off `bv-fixes` at `9b4f4c96` on
2026-09-06. It carries the CPC proof checking feature that lived on `cpcCheck` (based on the
old `alethe-toolkit` lineage), ported onto the current code base in two commits: the port
itself and a parser fix the cvc5 regressions exposed.

## Why a port and not a merge

`cpcCheck` had 41 commits not in `bv-fixes`, but only 6 were CPC work; the other 35 were the
toolkit lineage (aci_simp, arrays, la_mult_*, bvite, lambda/beta_equiv ...), which `bv-fixes`
already contains through the upstream PRs, and the crate had meanwhile moved from `carcara/`
to the repository root. `git merge-tree` reported 31 conflicting files. The CPC diff
(`cc775d7f^..cpcCheck`, 4,266 insertions in 21 files) was rewritten to the new paths and
applied with a three-way merge; the 13 conflicts were resolved by hand.

Adaptations needed: `Source`-based parser entry points, sorts as `Rc<Sort>` (`add_sort`),
`Proof::filename`, `declare_symbol`, flat indexed operators through
`allow_higher_order_indexed_ops` (the CPC-specific argument split was dropped), environment
style `let` expansion (the substitution-based expansion was dropped), the CLI's `app.rs`
option structs, the `Status` return type. The guarded `div_intro` axiom and `->` function
sorts already exist on `bv-fixes` (they arrived with the Alethe division and arrays work), so
the corresponding CPC hunks were dropped.

One semantic adaptation: `bv-fixes` applies a nullary definition whose body is a lambda as a
term (`((lambda ...) args)`), for `:named` lambdas in Alethe proofs. CPC `define`s of
functions are printed the same way but are macros for the problem's `define-fun`s, so in CPC
mode they are beta-reduced (otherwise two regress0 proofs fail their `assume`s).

## Fixes found by the sweep

- `quantifiers_skolemize_choice` (translator) rebuilt the choice term of every earlier
  variable once per later variable: exponential in the number of quantified variables.
  `regress1/quantifiers/smtlibe99bbe` (1.2 MB, 3,136 steps) parsed in 0.8 s but did not finish
  checking in 120 s; memoized by (quantifier, index) it checks in 0.19 s. This was a latent
  bug on `cpcCheck` too (the file timed out there as well).
- Parser (general, reproduces on the Alethe path with a dummy proof): a `:named a1` assertion
  in `regress1/proofs/alpha-eq-var-shadow` shadowed the RARE rule parameter `a1` of
  `bv-ashr-zero`, failing the rules file with "expected (_ BitVec ?), got Bool"; and a
  user-declared `set.member` in the AUFLIA problem `regress1/quantifiers/set8` was parsed as
  the sets operator. Declared or locally bound symbols now take precedence over nullary
  definitions and theory operators, as terms and as application heads.

## What changed around the translator since it was written

The translator mirrors cvc5's `alethe_post_processor.cpp` as of June 2026. Since then the
`alethebv` branch (`1eb17718e1`) reworked that file: Boolean ABSORB to `absorb`, bitblast
rules, the SCOPE implication/conjunction/clause round-trip short-circuits, `or_neg` one
resolution per distinct literal, `div_by_zero_intro` for the division-by-zero elimination,
translation-time subproof sharing, instantiation constants as skolem witnesses. None of it is
in the CPC translator; the translated proofs are therefore shaped like the pre-rework Alethe
output (SCOPE = subproof + and_pos/or_neg/resolution/reordering/contraction/implies_neg).
cvc5 main's CPC printer changes since June (to_real, quantifier rules, Lean/Logos) caused no
new parse failures in the sweep.
